# 學習筆記 02：轉向量（Embedding）與找出最相關的頁面

## 一句話說明

> 幫每一頁手冊在「意思地圖」上找座標；顧客問問題時，找出離問題最近的 3 頁。

## 回顧：為什麼需要這一步？

顧客問「**錢什麼時候會回到我帳戶？**」，這句話裡沒有「退款」兩個字。
如果只比對文字，電腦找不到「退款處理時程」那一頁。
用「意思地圖」的座標來比，就算用字不同，只要意思相近也找得到。

## 流程圖

```text
【事前準備：手冊有更新時才做】
python manage.py build_knowledge_index

  22 頁手冊 ──送給 Gemini──▶ 22 組座標 ──存起來──▶ knowledge_base/index.json


【每次查詢】
python manage.py search_knowledge "錢什麼時候會回到我帳戶？"

  問題 ──送給 Gemini──▶ 問題的座標
                          │
                          ▼
          和 index.json 裡的 22 頁一一比「相似度」
                          │
                          ▼
              分數最高的前 3 頁 ＝ 要給 AI 的小抄
```

## 名詞小辭典

| 名詞 | 白話 |
|---|---|
| Embedding（轉向量） | 幫一段文字算出它在「意思地圖」上的座標 |
| 向量（Vector） | 座標本身，就是一長串數字，例如 `[0.12, -0.53, ...]` |
| 相似度（Similarity） | 兩個座標有多接近，分數越高（最高 1）意思越像 |
| 索引（Index） | 事先算好、存起來的所有手冊座標，就像書後面的索引 |
| Top-K | 取前幾名，K=3 就是取前 3 名 |

## 為什麼要先存成 index.json？

手冊不常改，但顧客天天在問。
如果每次查詢都重新幫 22 頁算座標，等於每次都要付錢、等時間。
所以**先算好存起來**，查詢時只需要算「問題」那一句。

`index.json` 是電腦算出來的檔案，所以加進了 `.gitignore`，不放到 GitHub 上；每個人在自己電腦上產生即可。

## 動手做

> 前提：你的 `.env` 裡已經有 `GEMINI_API_KEY`（你的專案原本就有用到）。

**步驟 1：幫手冊算座標（只要做一次）**

```bash
python manage.py build_knowledge_index
```

成功會看到「已建立 22 頁的座標」。這一步會呼叫 Gemini 一次。

**步驟 2：問問題**

```bash
python manage.py search_knowledge "錢什麼時候會回到我帳戶？"
```

你會看到第 1～3 名的頁面和它們的相似度分數。

## 程式在哪裡？

主要都在 `myapp/retrieval_service.py`，分成 4 個區塊，**你只要看懂每塊在做什麼就好**：

| 區塊 | 函式 | 做什麼 |
|---|---|---|
| 1 | `embed_texts` | 把文字送給 Gemini，拿回座標 |
| 2 | `cosine_similarity` | 算兩個座標有多像（公式不用背） |
| 3 | `build_knowledge_index` | 幫 22 頁算座標，存成 index.json |
| 4 | `search_knowledge` | 問題轉座標 → 和 22 頁比分數 → 排序取前 3 名 |

## 小練習

**練習 1（動手）：** 執行下面三個問題，記下每個問題的**第 1 名**是哪一頁：

```bash
python manage.py search_knowledge "錢什麼時候會回到我帳戶？"
python manage.py search_knowledge "東西寄好久都沒來"
python manage.py search_knowledge "你們會不會送我折價券補償？"
```

第 1 名合理嗎？有沒有哪一題找得不太對？

**練習 2（思考）：** 第 1 名的分數大概是多少？如果顧客問「今天天氣好嗎？」，你猜分數會變高還是變低？試試看。

<details><summary>參考答案</summary>

和手冊完全無關的問題，分數會明顯比較低，但**還是會有第 1 名**，因為程式一定會挑出「相對最近」的 3 頁。
這是 RAG 的一個重要問題：**找不到相關資料時，系統要怎麼辦？** 之後我們會用「分數門檻」來處理，例如分數太低就不給 AI 小抄，讓它回答「需要轉人工」。

</details>

**練習 3（面試題）：** 用一句話說明：為什麼不直接用「關鍵字比對」來找手冊頁面？

<details><summary>參考答案</summary>

因為顧客的用字和手冊不一定相同，例如「錢什麼時候回來」和「退款處理時程」沒有共同的關鍵字；Embedding 比的是「意思」而不是「字面」，所以找得到。

</details>
